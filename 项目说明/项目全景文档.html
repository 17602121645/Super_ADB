📊 项目概览

基于 PySide6 的 Android ADB 桌面工具集，支持设备管理、文件传输、性能监控、证书安装、WiFi 调试等功能。

主题切换流程：_切换主题 → setStyleSheet → 刷新标题栏按钮 → 延迟 _强制主题重绘 → 同步打开中的弹窗样式。

弹窗样式跟随主题（正确做法）

# 1. 创建弹窗：只给对话框 setStyleSheet，子控件不单独设样式
dlg = QDialog(self)
dlg.setStyleSheet(get_stylesheet(self._current_theme))
# QLabel / QTextEdit 等子控件自动继承全局主题样式，不要 setStyleSheet

# 2. 主题切换时同步更新打开的弹窗（在 _切换主题 中）
if hasattr(self, '_设备信息弹窗') and self._设备信息弹窗 is not None:
    self._设备信息弹窗.setStyleSheet(get_stylesheet(theme_id))

# ❌ 错误：子控件写死颜色，切换主题后不变
label.setStyleSheet('color:#58a6ff;background:#0d1117')
edit.setStyleSheet('QTextEdit{background:#0d1117;color:#e6edf3}')

自研 ADB 协议栈（工具/自研adb/）

不依赖官方 adb 二进制的纯 Python ADB 实现，TCP/USB 双通道，与官方 adb 可切换。11个模块，共约6552行。支持无线配对（SPAKE2+AES-GCM）、原生 WinUSB 后端、连接池、scrcpy 投屏、ADB交互式终端。

adb协议.py — 协议层（1744行）

实现 CNXN/AUTH/OPEN/WRTE/CLSE 状态机与 sync 协议。认证：RSA2048 + SHA1 PKCS1v15 签名；公钥为 524 字节 android_pubkey_t 的 base64。ADB_VERSION=0x01000001（skip checksum）。_定位密钥路径() 统一解析密钥位置：打包版放 exe 旁 配置/ 并自动迁移已授权密钥。

自研adb客户端.py — 连接池（672行）

设备级建连锁（RLock）+ 连接池借用/剥离；30 秒负缓存防认证失败重试风暴；公钥授权 60 秒循环等待；主连接模式（短操作共享主连接加锁串行，长操作用独立连接）；认证失败原因精确上报。

usb连接.py + usb传输层.py

USB ADB 传输层，与 TCP 共用同一份密钥。双后端架构：Windows 优先原生 WinUSB（SetupAPI+WinUSB，不依赖 libusb），回退 pyusb/libusb1。支持 USB 设备热插拔检测、设备枚举、端点查找。

usb窗口原生.py — 原生 WinUSB 后端（869行）

Windows 原生 USB 实现，纯 ctypes 调用 SetupAPI + WinUSB，无需安装 libusb。通过 ADB 接口 GUID 枚举设备 + 暴力枚举全量USB接口兜底 + 设备节点诊断（检测无驱动设备），CreateFileW + FILE_FLAG_OVERLAPPED 打开，WinUsb_Initialize 初始化，Bulk 端点读写。支持从父设备实例 ID 读取序列号。

scrcpy会话.py — scrcpy会话（910行）

推送 scrcpy-server、建立视频 socket、解析 H.264 流配置，交给投屏客户端渲染。支持reverse模式。

配对客户端.py — 无线配对客户端（686行）

Android 11+ 无线调试配对实现。TLS 连接 + SPAKE2+ 密钥交换 + AES-128-GCM 加密通信。支持配对码模式，生成自签名证书，导出 TLS 密钥材料。与官方 adb pair 命令兼容。

配对认证.py + 密钥交换算法.py

配对认证层：AES-128-GCM 加解密、SPAKE2+ 椭圆曲线密钥交换（纯 Python 实现 Curve25519 标量乘法）。支持客户端/服务端双向认证，口令派生密钥，密钥确认。

多设备管理器.py

多设备连接管理，统一调度各设备的连接池和认证状态。

投屏解码链路（工具/）

投屏客户端.py + h264解码器.py

scrcpy 视频流 → h264解码器（ctypes 封装内置 openh264，外部扩展/openh264/，~4MB）→ OpenGL 纹理渲染。已弃用 PyAV（其 hook 会收集全量 ffmpeg 编码器 62.5MB）。解码器接口兼容原 av 用法，设备不支持 H.264 时优雅降级提示。

⚡ 性能测试

USB 上传/下载速度对比：自研ADB vs 官方 adb。实测 128MB 随机文件、各 3 轮取平均（同一把 super_adb_key 密钥、官方 adb 以 ADB_VENDOR_KEYS 指定并 -s 锁定 USB 设备）。

⚡ USB 上传/下载速度（实测结果）

测试条件：荣耀 ELZ-AN20 · USB 直连 · 官方 adb 以 -s 锁定 USB 设备 · 128MB 随机数据 · 各方向 3 轮取平均 · 自研ADB 走 sync 协议（64KB DATA 块 × 15 块/帧合并发送）；官方 adb 1.0.41 走标准 sync 协议， 同一把 super_adb_key 密钥。

方向实现第1轮第2轮第3轮平均 / 速率
上传 push自研adb3.24s3.23s3.18s3.22s · 39.8 MB/s
上传 push官方adb3.54s4.73s3.51s3.93s · 32.6 MB/s
下载 pull自研adb3.17s3.13s3.13s3.15s · 40.7 MB/s
下载 pull官方adb3.15s3.14s3.22s3.17s · 40.4 MB/s

结论

  • 上传（push）：自研 39.8 MB/s vs 官方 32.6 MB/s，快约 22%。自研把多个 64KB DATA 块合并进同一个 WRTE 帧（每帧最多 15 块），把 137 次往返降到 9 次；官方 adb 每帧只发一块、等流控 OKAY 后才发下一块。
  • 下载（pull）：自研 40.7 MB/s vs 官方 40.4 MB/s，基本持平。两者均已接近 USB 2.0 总线实际吞吐上限（约 40MB/s）。

🏗️ 架构机制

线程模型、单实例、窗口持久化、日志系统等核心机制。

🔀 三种ADB模式

系统adb：调用PATH中的adb.exe，最稳定。Socket直连：直连127.0.0.1:5037，不启动adb进程。自研ADB：纯Python实现ADB协议，直连设备5555端口，无需官方adb。

🧵 线程模型

命令工作器(QRunnable) + QThreadPool 异步执行 ADB 命令，避免阻塞 UI。结果通过 工作器信号 信号回传（result/error/finished）。长任务用 QThread（如安装线程、哈希线程）。

🔒 单实例机制

单实例(QObject) 通过系统互斥量（mutex）防止多开。第二个实例启动时检测到已有实例，自动退出并激活已有窗口。

📐 窗口几何持久化

启动时从配置读取 geometry.b64（saveGeometry 的 base64 编码），调用 restoreGeometry() 恢复窗口位置/大小/状态。关闭时 saveGeometry() 写入配置。

📝 日志输出系统

三级输出：日志() 输出框（主窗口文本区）、设置状态() 状态栏（底部提示，带成功/失败颜色）、日志查看器页（logcat 实时流）。

🔑 自研ADB认证与密钥管理

密钥 super_adb_key(+.pub) 源码模式在 配置/，打包版在 exe 旁 配置/（首次访问自动从旧位置/源码树迁移）。认证失败后 30 秒负缓存冷却；发公钥后 60 秒循环等待设备授权（盒子/TV 等无授权弹窗的 ROM 会断开连接，错误消息提示复制已授权密钥）。无线配对：Android 11+ 配对码模式，SPAKE2+ 密钥交换 + AES-128-GCM 加密，与官方 adb pair 兼容。

🎬 投屏 H.264 解码链路

scrcpy-server 推送 H.264 NAL → h264解码器（ctypes 调 openh264 DLL）→ YUV → OpenGL 纹理上屏。解码线程与渲染线程解耦，停屏时快速退出并释放解码器。

🔗 连接池架构

自研ADB采用设备级建连锁 + 连接池。短操作（shell命令）共享主连接加锁串行；长操作（推送/拉取/安装）用独立连接。后台daemon线程清理空闲连接。

注意事项

⚠️ 循环导入：Mixin 文件中如需导入主入口的类（如 命令工作器），必须在方法内部延迟导入，不能在文件顶部导入。
⚠️ UI 定义分离：新增按钮/控件必须在 .ui 文件中定义，编译后代码只做样式和信号连接。不要在代码中动态创建 UI 控件。
⚠️ 中文命名：新建文件/类/方法/变量一律使用中文命名。历史英文代码保持不变，重构时逐步迁移。
⚠️ 包式导入：所有 import 使用包名前缀（from 对话框.xxx import ...），不要使用裸导入。sys.path 只加 Super_ADB_Win/ 根目录。
⚠️ 线程安全：ADB 命令必须异步执行（QThreadPool + QRunnable），不能在主线程直接调用。结果通过信号回传。
⚠️ 主题传播：自定义对话框必须实现 apply_theme(theme_id) 方法，主题切换时会自动调用。无边框对话框需手动同步样式。
⚠️ 弹窗控件样式勿写死：弹窗内的 QLabel / QTextEdit / QPushButton 等子控件不要单独调用 setStyleSheet 写死颜色（如 color:#58a6ff;background:#0d1117），否则会覆盖全局主题，切换主题后控件样式不变。正确做法：只给对话框本身 setStyleSheet(get_stylesheet(theme_id))，子控件自动继承全局样式（界面样式.py 已定义 QTextEdit/QLabel/QPushButton 等主题样式）。若必须自定义，用 THEMES[theme_id] 取色并在主题切换时重新 apply。弹窗打开状态下切主题：在 _切换主题 中检查 self._xxx弹窗 是否存在，存在则调用 setStyleSheet(get_stylesheet(新主题))。参考：设备信息弹窗实现。
⚠️ 实例复用：弹窗打开方法必须检查实例是否已存在且可见，重复点击应 raise 而非新建。关闭后通过 destroyed 信号清空引用。
⚠️ 设备序列号：对话框标题应包含设备信息（xxx — 设备: {serial}），通过 get_serial() 回调获取，未连接时显示「未连接设备」。
