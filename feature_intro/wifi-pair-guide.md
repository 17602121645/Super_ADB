> 适用版本：Super_ADB Main 2026-08-08+
> 模块位置：`Super_ADB_Main/dialogs/wifi_pair_dialog.py`
> 关联文件：`Super_ADB_Main.py`（入口 `open_wifi_pair`）、`adb_utils.py`（底层 adb 子进程调用）

## 一、功能概览

Android 11（API 30）起，手机「无线调试」默认不再让用户自选 5555 端口直接 `adb connect`，而是要求**「配对」**后才能连接。新流程在桌面上长这样：

```
1. 手机：设置 → 开发者选项 → 无线调试 → 「使用配对码配对设备」
2. 手机弹出小窗：「IP 地址 192.168.1.16」「端口 38973」「配对码 016813」
3. 电脑：adb pair 192.168.1.16:38973 016813          ← 一次性「配对」
4. 电脑：adb connect 192.168.1.16:5555              ← 用调试端口「连接」
```

「WiFi 配对码连接」弹窗把第 3、4 步包装成一个 GUI：

- 输入 IP、**配对端口**、**6 位配对码**（或一键粘贴手机弹窗原文自动拆分）
- 后台跑 `adb pair`，绝不卡死 UI
- 配对成功后再一键 `adb connect` 调试端口（默认 5555）
- 完成后自动回填到主窗口的「输入 IP」框 + 刷新设备列表

### 为什么不能直接 `adb connect`

- 配对端口（`38973` 这种）只在「配对」过程中有效，**配对一次后即过期**，下次要重新配对
- 调试端口（`5555`）配对成功后才能正常 connect
- 没配对就 connect，会报 `failed: Pairing required` / `failed to connect to /192.168.1.16:5555`

所以 **pair 和 connect 是两件事**，必须分两步走。

### 它解决什么

| 痛点 | 这个功能怎么治 |
|------|----------------|
| 在命令行手动输 `adb pair ip port code` 容易输错 | GUI 三个输入框 + 正则/QIntValidator 校验 |
| 手机弹窗里的文本太多，眼睛看着累 | 「📋 粘贴」按钮从剪贴板自动解析 `IP`/`端口`/`配对码` |
| `adb pair` 可能 5-10s 才有返回，卡住命令行 | 后台 `_PairWorker(QThread)` 跑，UI 状态栏实时刷新 |
| 配对成功了，调试端口还要再开一次 connect | 「连接调试端口」按钮一键搞定，超时 12s 不会卡死 |
| 配对成功后还要回主窗口设备列表看一眼 | `on_pair_success` 回调自动 `refresh_devices()` + 把 IP 回填到主窗口 `ipInput` |
| 端口配对和 connect 之间忘了哪一步做了 | 结果区滚动日志 + 状态栏文字（`正在配对 / 配对成功 / 正在连接 / 已连接`） |

## 二、入口与触发

- **位置**：主窗口「设备连接」区，**「WiFi 配对」按钮**（与「连接」「局域网扫描」并列）。
- **行为**：点击后弹出独立 `QDialog` 窗口；标题「WiFi 配对码连接」。
- **重复点击**：窗口已开就 `raise_()` + `activateWindow()` 前置，不重复开。

```python
# Super_ADB_Main.py:1027
def open_wifi_pair(self):
    """打开 WiFi 配对码连接弹窗（复用窗口，重复点击 raise）。"""
    if self._wifi_pair_dialog is not None and self._wifi_pair_dialog.isVisible():
        self._wifi_pair_dialog.raise_()
        self._wifi_pair_dialog.activateWindow()
        return

    def _on_pair_success():
        # 配对成功后刷新设备列表，并把当前 IP 填到主窗口输入框方便下一步 connect
        ip = self._wifi_pair_dialog.ip_edit.text().strip() if self._wifi_pair_dialog else ''
        port = (self._wifi_pair_dialog.debug_port_edit.text().strip()
                if self._wifi_pair_dialog else '5555')
        if ip and port:
            self.ipInput.setText(f'{ip}:{port}')
        self.refresh_devices()

    self._wifi_pair_dialog = WifiPairDialog(parent=self, on_pair_success=_on_pair_success)
    self._wifi_pair_dialog.show()
```

### 关键 UI 细节

- **IP 框容忍 `IP:端口` 格式**：在 IP 框里直接粘贴 `192.168.1.16:38973`，会自动拆成 IP=`192.168.1.16`、配对端口=`38973`，光标跳到配对码框（`_on_ip_text_changed`）
- **配对码 6 位数字正则**：`QRegularExpressionValidator(r"\d{0,6}")` + `setMaxLength(6)`，输到第 7 位会被吞掉
- **配对端口 / 调试端口**：`QIntValidator(1, 65535)`，防止「空格」「负数」「字母」混进去
- **连接调试端口初始禁用**：必须等「配对」成功才点亮 `_on_pair_done` 设 `btn_connect.setEnabled(True)`
- **粘贴按钮智能解析**：剪贴板文本支持三种常见写法：
  ```
  192.168.1.16:38973 016813
  IP 地址和端口 192.168.1.16:38973
  WLAN 配对码 016813
  ```
  用正则 `(\d{1,3}(?:\.\d{1,3}){3}):(\d{1,5})` 抓 IP:端口 + `配对码[:：\s]*(\d{6})` 抓 6 位数字
- **状态栏颜色随阶段切换**：默认青绿（`ACCENT`）；失败/超时后改文字保留 ACCENT 但内容带 ❌ 前缀

### 1. 手机端操作

```
设置 → 开发者选项 → 无线调试 → 打开「无线调试」
                  → 「使用配对码配对设备」
```

手机弹出这样的小窗：

```

│                              │
```

### 2. 桌面端操作

**方式 A：手动输入**

1. 主窗口点「WiFi 配对」按钮
2. 在弹窗的 3 个框里分别填：IP=`192.168.1.16`、配对端口=`38973`、配对码=`016813`
3. 调试端口一般默认 `5555`，如果要改也支持（少数手机用别的）
4. 点「🔑 开始配对」→ 状态栏变「正在配对 …」→ 几秒后输出区冒出 `$ adb pair ...` 和结果

**方式 B：粘贴**

1. 在手机弹窗上点「复制」（Android 把内容复制到剪贴板）
2. 电脑点「📋 粘贴」→ 3 个框自动填好
3. 继续方式 A 的步骤 4-7

**方式 C：粘贴 IP:端口 到 IP 框**

1. 复制粘贴 `192.168.1.16:38973` 到 IP 框（光标先到 IP 框）
2. 自动拆分成 IP=`192.168.1.16` + 配对端口=`38973`，光标跳到配对码框
3. 输入或粘贴配对码，继续走流程

## 五、内部实现

### 架构

```
┌─────────────────────────────────────────────────────────┐
│  WifiPairDialog (QDialog, UI 线程)                    │
│    ├─ ip_edit, port_edit, code_edit, debug_port_edit  │
│    ├─ btn_pair ─clicked→ _start_pair                  │
│    ├─ btn_connect ─clicked→ _start_connect            │
│    ├─ output (QTextEdit) ← _log                       │
│    └─ status_lbl                                      │
├─────────────────────────────────────────────────────────┤
│  按需启动的后台线程（一次一个）                          │
│    ├─ QThread #1                                       │
│    │    └─ _PairWorker  ← run() 跑 `adb pair ...`      │
│    │            └─ done(ok, msg) → _on_pair_done       │
│    └─ QThread #2（pair 成功后才启动）                     │
│         └─ _ConnectWorker ← run() 跑 `adb connect ...`│
│                 └─ done(ok, msg) → _on_connect_done   │
└─────────────────────────────────────────────────────────┘
```

### 关键代码

```python
# 后台 pair（绝不阻塞 UI）
class _PairWorker(QObject):
    done = Signal(bool, str)

    def run(self):
        if self._cancelled:
            return
        try:
            from adb_utils import AdbHelper
            adb = AdbHelper()
            cmd = [adb.adb_path, 'pair', self._target, self._code]
            cmd_str = adb._cmd_str(cmd)
            result = subprocess.run(
                cmd_str, capture_output=True, text=True,
                timeout=20, creationflags=CREATE_NO_WINDOW, shell=True,
            )
            combined = (result.stdout or result.stderr or '').strip()
            ok = (result.returncode == 0
                  and ('successfully paired' in combined.lower()
                       or '配对成功' in combined
                       or 'successfully' in combined.lower()))
            self.done.emit(ok, combined)
        except subprocess.TimeoutExpired:
            self.done.emit(False, "❌ 配对超时（20s）…")
        except Exception as e:
            self.done.emit(False, f"❌ 配对异常：{e}")
```

- **timeout=20s**：手机弹窗 + WiFi 配对握手可能需要 3-10s，超过 20s 视为失败
- **返回判断三重保险**：returncode=0 + `successfully paired` 或中文「配对成功」或泛 `successfully`
- **closeEvent 同时 cancel 两个 worker**：避免窗口关了后台子进程还活

### 状态转换

```
[初始]
  ↓ 点「开始配对」
[pair 中]
  ├─ 成功 → [pair 成功] → 「连接调试端口」按钮亮起 → 点 → [connect 中]
  │                                                              ├─ 成功 → accept() 关弹窗 + 主窗口设备列表刷新
  │                                                              └─ 失败 → 弹窗留状态栏红字，可重试
  ├─ 失败/超时 → [pair 失败] → 状态栏红字，可改 IP/端口/码 再试
  └─ 关窗 → cancel 两个 worker + wait(2s) → accept
```

`closeEvent` 是关键保护：

```python
def closeEvent(self, event):
    self._closing = True
    for w in (self._pair_worker, self._connect_worker):
        if w is not None:
            try: w.cancel()
            except Exception: pass
    for t in (self._pair_thread, self._connect_thread):
        if t is not None and t.isRunning():
            t.quit()
            t.wait(2000)
    event.accept()
```

## 六、故障排查

### 1. 「配对超时（20s）：手机可能未开启「使用配对码配对设备」或网络不通」

| 检查项 | 命令 |
|------|-----|
| 手机无线调试已开 | 手机「设置 → 开发者选项 → 无线调试」开关亮起 |
| 配对码弹窗已弹出 | 手机点「使用配对码配对设备」，看到 6 位数字 |
| 电脑和手机同网段 | 电脑 `ping 192.168.1.16` 应通 |
| 防火墙没拦 | `adb` 走 TCP 端口对，需要放行 `192.168.1.16:38973` 出/入 |

### 2. 「❌ 配对异常：Permission denied / cannot find adb」

- 检查 `adb version` 能不能在主窗口「输出」框出来（说明 adb 配置正常）
- 路径有空格/中文时 `adb_path` 用引号包了仍可能错；可尝试把 adb 放到无空格路径

### 3. 「❌ 配对成功但「连接调试端口」一直失败」

- 配对端口是一次性的，**配对完成后立即 connect**，等待 >30s 就会过期
- 调试端口填错：手机「无线调试」页面正下方显示的是调试端口（截图里能看到「192.168.1.16:5555」字样），**不是配对端口**
- 设备没在同一网段：手机切换过 WiFi 或 VPN

### 4. 「输出区 `$ adb pair ...` 后没结果」

- 后台线程被 closeEvent 提前 `cancel()` 了；如果是想再配一次，直接重新填码再点「开始配对」即可
- 如果「开始配对」按钮点不下去，是因为 `_closing=True` 已设（场景：弹窗关闭后再开窗口）。重启程序即可

```
主窗口设备连接区
  ├─ 连接的设备 [已连接设备下拉]  ←─── on_pair_success 回调 refresh_devices() 后填充
  │                                        ↑
  ├─ [断开连接]                              │
  ├─ [刷新连接列表]                          │
  ├─ [建立连接: 输入IP (无法连接尝试...) ][连接][局域网扫描][WiFi 配对]──┐
  │                                                                          │
  │                     ┌────────────────────────────────┘
  │                     ▼
  │              WifiPairDialog
  │                ├─ 配对成功后,on_pair_success → 主窗口
  │                │    ├─ ① ipInput.setText(f'{ip}:{port}')  → 用户可手动点主窗口「连接」
  │                │    └─ ② refresh_devices()              → 设备列表自动多出此机
  │                └─ 连接调试端口成功后 → accept 关弹窗
```

两套入口互补：

- **WiFi 配对**：知道设备 IP、要走一次性配对流程（Android 11+ 强制）
- **局域网扫描**：不知道设备 IP、要扫网段（多用于发现多台调试机 / 网络拓扑未明时）

## 八、设计要点（可复用）

1. **三件事三输入**：IP / 配对端口 / 配对码三个语义独立的字段分别校验（正则 + QIntValidator + maxLength），比让用户手写一大串命令稳很多。
2. **状态机驱动 UI**：pair 完成 → enable connect 按钮；connect 完成 → accept 关弹窗。中间态（pair 中 / connect 中）禁用所有按钮 + 改状态栏文字。
3. **剪贴板降级操作**：Android 弹窗的文本格式不可控，正则要宽松（`配对码[:：\s]*(\d{6})`），匹配失败给「无法自动解析」而不是抛异常。
4. **后台 worker + done 信号**：adbsubprocess 全跑 `QThread + QObject.moveToThread`，signal 跨线程汇报，绝不让主线程等 `pair`/`connect`。
5. **cancel + quit + wait 二段式关闭**：closeEvent 先 `worker.cancel()` 把标志位置位（worker 内部会跳过下一步 adb），再 `thread.quit() + thread.wait(2000)` 让事件循环干净收尾。
6. **on_pair_success 回调解耦 UI**：弹窗不持有主窗口引用，通过回调把「配对成功」这个事件抛出去，让主窗口决定刷新设备列表 / 回填 IP 输入框。配对端口用一次就过期这种问题，弹窗本身不感知，逻辑更干净。

## 九、典型用例

### 用例 1：同一 WiFi 下首次连接新手机

> 场景：测试部新到一台小米 14，要接进电脑跑自动化脚本。

```
手机：设置 → 开发者选项 → 无线调试 → 打开
       →「使用配对码配对设备」→ 记下 IP 192.168.1.102 / 端口 41822 / 码 284516
电脑：主窗口「WiFi 配对」→ 手动填三框 → 开始配对 → 配对成功
       →「连接调试端口」（调试端口 5555）→ 弹窗自动关 + 主窗口设备列表多出 192.168.1.102:5555
脚本：adb -s 192.168.1.102:5555 shell ... 可直接用
```
**收益**：不用插线、不用记命令，配对→连接 30 秒内搞定。

### 用例 2：设备调试端口被改过（非默认 5555）

> 场景：某系统 App 占用了 5555，手机「无线调试」显示调试端口是 `37800`。

```
手机弹窗：IP 192.168.1.50 / 配对端口 39011 / 配对码 771203 / 调试端口(无线调试主页) 37800
电脑：IP + 配对端口 + 配对码 正常填
      调试端口框手动改 37800（默认 5555 不可用时改这里）
      开始配对 → 连接调试端口 → 连上 192.168.1.50:37800
```
**收益**：调试端口是独立字段，默认 5555 但可改，适配端口被占情况。

### 用例 3：粘贴流（最快路径）

> 场景：手机弹窗点「复制」后，电脑直接粘贴。

```
手机：弹窗内「复制」→ 剪贴板 = "192.168.1.88:40822\nWLAN 配对码 550217"
电脑：主窗口「WiFi 配对」→「📋 粘贴」→ IP/端口/码 三框自动填好
      开始配对 → 连接调试端口
```
**收益**：复制→粘贴→两下点击，全程不碰键盘打字。

### 用例 4：批量铺设备（多手机同型号）

> 场景：产线要一次性把 10 台同型号手机都配上无线调试。

```
对每台：弹「配对码」→ 复制 → 本机粘贴填框 → 开始配对 → 连接调试端口 → 关弹窗
        下一台：重新「WiFi 配对」→ 弹窗复用（raise 不新建）→ 同样流程
```
**收益**：弹窗复用（`open_wifi_pair` raise 已开的窗口），反复开关不泄漏。

### 用例 5：配对成功但后续连接失败（排查流）

> 场景：弹窗说「配对成功」，但「连接调试端口」一直 failed。

```
排查：看故障排查章节 §六
  - 是不是等太久（配对端口 30s 过期）→ 重新配对立即连
  - 调试端口填错（填成配对端口了）→ 改回 5555 或手机显示的真实调试端口
  - 手机切了 WiFi/开了 VPN → 回到同网段
```
**收益**：弹窗状态栏 + 输出区把每一步 adb 返回都留痕，排查有据可依。

> 这些是当前未做、但有明确价值的方向，按投入产出排序。

### P1（高价值 / 低成本）

1. **「连接调试端口」失败自动重试 + 端口列表探测**
   - 现状：失败只弹窗报红，用户自己猜端口。
   - 可做：连接失败时扫一遍 5555 / 37800 / 当前网段常见调试端口，或读手机「无线调试」主页的调试端口（需要 `adb` 读系统属性），自动重试正确的那个。
   - 收益：把「调试端口填错」这类 80% 的失败变零操作。

2. **粘贴解析失败给具体原因**
   - 现状：解析失败一律「剪贴板内容无法自动解析」。
   - 可做：细分「找不到 IP:端口」「找不到 6 位配对码」，甚至提示「配对码只有 5 位？手机上确认下」。
   - 收益：用户不用对着空框发懵。

3. **配对成功后自动开始 connect（一步到位）**
   - 现状：pair 成功 → 用户再点一次 connect。
   - 可做：加个「配对成功后自动连接」勾选框（默认勾），`on_pair_done(ok=True)` 自动触发 `_start_connect`。
   - 收益：把两步合成一步。

### P2（中等价值 / 需设计）

4. **多设备排队配对**
   - 现状：一次对一个 IP。
   - 可做：IP 列表输入（每行一个），串行/并发 pair + connect，结果区逐条汇总。
   - 收益：用例 4 的批量铺设备可以一次导入 10 台。

5. **配对状态持久化 + 自动重连**
   - 现状：配对端口用一次就过期，重连要重新 pair。
   - 可做：记录「已配对设备指纹」（如手机序列号），WiFi 重连后尝试直接 connect（部分 ROM 配对一次后调试端口长期有效）。
   - 收益：日常开发少点几次。

6. **二维码配对（Android 11+ 也有 QR 配对流）**
   - 现状：只支持「配对码」流程。
   - 可做：加一个「扫码配对」tab，读手机「无线调试」主页的二维码（含 IP/端口/配对码），等价于自动粘贴。
   - 收益：比手动复制更快，且不依赖剪贴板跨设备同步。

### P3（探索性）

7. **与「局域网扫描」合并成统一无线调试入口**
   - 现状：两个独立弹窗（扫描发现 / 配对连接）。
   - 可做：扫描发现设备后，对「未配对」的直接内联「配对」入口，对「已配对未连接」内联「连接」。
   - 收益：用户心智模型从「两个工具」变成「一个无线调试面板」。

8. **配对日志导出 / 历史记录**
   - 可做：把每次 pair/connect 的时间、IP、结果存本地历史，出问题可回溯「昨天那台 192.168.1.88 到底配成功没」。
