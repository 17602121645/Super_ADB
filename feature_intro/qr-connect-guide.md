# 「二维码连接」功能介绍

> 适用版本：Super_ADB Main 2026-08-09+
> 模块位置：`Super_ADB_Main/dialogs/qr_connect_page.py`
> 父容器：`Super_ADB_Main/dialogs/wireless_debug_dialog.py`（「无线调试」弹窗的第三个标签页）
> 依赖：`segno`（生成二维码）、`zeroconf`/`ifaddr`（mDNS 监听）、`cv2`（扫码识别）

---

## 一、功能概览

「二维码连接」标签页把手机和电脑之间的无线配对二维码做成**双向**工具：

- **📷 扫码（手机 → PC）**：识别手机「无线调试 → 使用二维码配对设备」弹出的二维码，提取 IP / 配对端口 / 配对码，一键回填到「配对码连接」页。
- **🔳 生成（PC → 手机）**：本机生成配对二维码，手机扫描后由 Super_ADB 通过 mDNS 自动完成 `adb pair`，全程无需手动输入。

它是「无线调试」弹窗（[总文档](wireless-debug-guide.md)）的第三个标签页，与「配对码连接」页联动——扫码结果可一键跳转回填。

### 它解决什么

| 痛点 | 这个功能怎么治 |
|------|----------------|
| 手机二维码只显示几秒，记不住 IP / 端口 / 配对码 | 截图后「从剪贴板图片扫码」或选文件，自动解析三要素 |
| 手动在电脑里敲 `adb pair` 一行长命令容易错 | 「填入配对页」一键跳到配对页并回填，再点「开始配对」 |
| 手机扫电脑二维码还要手动输配对码 | 生成二维码时自动跑 mDNS 监听，手机扫完 Super_ADB 自动发现并执行 `adb pair` |

## 二、入口与触发

- **位置**：主窗口「设备连接」区 → **「无线调试」** 按钮 → 「无线调试」弹窗 → **第三个标签页「二维码连接」**。
- **行为**：点击「无线调试」默认停留在上一次关闭时的标签页。
- **重复点击**：窗口已开就 `raise_()` + `activateWindow()` 前置，不重复开。
- **空状态**：未生成二维码时，预览区显示「二维码预览区（点击上方按钮生成）」占位文字。

## 四、扫码（手机 → PC）

### 4.1 两种扫码来源

- **从剪贴板图片扫码**：直接读取剪贴板里的图片（截图后无需保存文件），用 `cv2.QRCodeDetector` 识别。
- **选择图片文件扫码**：选一张 PNG/JPG/BMP，识别其中的二维码。

### 4.2 识别后处理

识别到二维码内容后，按 `WIFI:T:ADB;S:<服务名>;P:<配对码>;;` 格式解析出手机的 **IP / 配对端口 / 配对码**，并显示在上方结果框。

### 4.3 一键回填

点 **「填入配对页」** 自动切到「配对码连接」标签页，并把解析到的 IP / 端口 / 配对码回填到对应输入框，再点「开始配对」即可完成连接。

## 五、生成二维码（PC → 手机，扫描后自动配对）

### 5.1 生成流程

1. **配对码**：可留空（自动随机生成 6 位数字），也可手动输入。
2. **服务名**：由 Super_ADB 自动生成（如 `superadb-AB12CD`），无需用户关心。
3. 点 **「生成二维码并开始等待」**：
   - 本页预览二维码（画布 200×200）；
   - **自动启动 mDNS 监听**（`zeroconf` 监听 `_adb-tls-pairing._tcp`）等待手机扫描；
   - 状态行实时显示「等待手机扫描 / 已发现手机 / 配对成功或失败」。
4. 用手机「无线调试 → 使用二维码配对设备」扫描电脑上的二维码（或点「弹窗大图」后的大图）。
5. 手机会按服务名在局域网广播一条配对服务，**Super_ADB 监听到后自动提取手机 IP:端口并执行 `adb pair`**，无需手动输入。
6. 配对成功后主窗口设备列表自动刷新。

### 5.2 辅助操作

- **🔍 弹窗大图**：弹出独立大窗口展示二维码，类似 Android Studio「Pair Devices Using Wi-Fi」的二维码窗口。
- **📋 复制**：复制二维码原始 payload 文本。
- **⏹ 停止等待**：随时取消 mDNS 监听，不再自动配对。

## 六、二维码格式说明

```text
WIFI:T:ADB;S:<服务名>;P:<配对码>;;
```

| 字段 | 含义 |
|------|------|
| `T:ADB` | 固定标识，表示这是 Android 无线调试配对 |
| `S:<服务名>` | **服务名**（如 `superadb-AB12CD`），手机用它来广播本机的 mDNS 配对服务；**不是 PC 的 IP:端口** |
| `P:<配对码>` | 6 位配对码 |

> ⚠️ 常见误区：旧版曾把 `S` 写成 PC 的 `IP:端口`，导致手机扫描后毫无反应——因为手机需要的是「服务名」来广播自己的 mDNS 配对服务，而 PC 端必须由 Super_ADB 去发现该服务再 `adb pair`。当前版本已修正此问题。

## 七、典型使用流程

### 场景 A：电脑扫手机二维码，快速回填配对

1. 手机：进入「无线调试 → 使用二维码配对设备」，屏幕显示二维码。
2. 电脑：点「无线调试」→ 切到「二维码连接」→「从剪贴板图片扫码」或「选择图片文件扫码」。
3. 识别成功后点「填入配对页」，自动跳到「配对码连接」页并填好字段。
4. 点「开始配对」，再连调试端口。

### 场景 B：手机扫电脑二维码，自动配对

1. 电脑：点「无线调试」→ 切到「二维码连接」。
2. 配对码留空（自动随机），点「生成二维码并开始等待」。
3. 手机：进入「无线调试 → 使用二维码配对设备」，扫描电脑上的二维码（或「弹窗大图」后的大图）。
4. 电脑端状态变为「已发现手机 … 正在执行 adb pair」，数秒后提示「✅ 配对成功」，设备列表自动刷新。

## 八、依赖与线程模型

- **生成**：`segno` 纯 Python 生成二维码，`zeroconf` + `ifaddr` 做 mDNS 监听（独立后台线程，关闭标签页时随父窗口统一 `cleanup()`）。
- **扫码**：`cv2.QRCodeDetector` 在 UI 线程执行（图片解码本身很快），无需后台线程。
- **生命周期**：作为 `wireless_debug_dialog` 的嵌入子页，其 `closeEvent` 不会单独触发；关闭「无线调试」弹窗时统一调用 `cleanup()`，停掉 mDNS 监听线程，避免悬挂。
- 上述三个依赖已写入 `requirements.txt`，冻结构建已加入 `--hidden-import segno`、`--hidden-import zeroconf,ifaddr`。

## 九、常见问题

| 现象 | 排查 |
|------|------|
| 生成二维码后手机扫描无反应 | 确认手机在「无线调试 → 使用二维码配对设备」界面；电脑与手机需同一网段；防火墙未拦 mDNS（5353/UDP） |
| 状态一直「等待手机扫描」 | Super_ADB 还没监听到配对服务；检查 `zeroconf` 是否正常启动（看日志） |
| 扫码识别失败 | 截图要清晰、二维码完整入镜；优先「从剪贴板图片扫码」避免二次压缩 |
| 「填入配对页」点了没反应 | 二维码内容不是 `WIFI:T:ADB;...` 标准格式，无法解析出三要素 |
