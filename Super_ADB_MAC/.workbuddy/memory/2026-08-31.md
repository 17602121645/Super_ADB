## 「扫码链接 手机端一直转圈」根因与修复

- **现象**：扫码配对时手机端一直转圈，配对永不完成。
- **根因**：纯 Python 自研配对客户端（`工具/自研adb/配对客户端.py`）在 TLS 握手后必须调用
  `SSL_export_keying_material`（label=`adb-label\x00`，64 字节）导出 SPAKE2 密码。但本机打包用的
  CPython 3.13（静态链接 OpenSSL 3.5.5，_ssl 为 builtin、无独立 libssl、_ssl._SSLSocket 不暴露 SSL*
  指针）**不提供 `ssl.SSLSocket.export_keying_material`**；旧 ctypes 偏移法在该构建上会 SIGSEGV。
  于是握手永远卡在密钥导出 → 手机一直转圈。mDNS/zeroconf 收集正常（非根因）。
- **修复（三层）**：
  1. `配对客户端.py`：`导出tls密钥材料()` 改为只走标准库（无则安全返回 None）；新增
     `进程内配对是否可用()`（= `hasattr(ssl.SSLSocket,'export_keying_material')`）做**事前**能力检测，
     避免在手机单次扫码配对会话上发起注定失败的 TLS 连接（否则会占用配对槽、连带 `adb pair` 也失败）。
  2. `ADB工具.py`：`配对设备()` 先判 `进程内配对是否可用()`，不可用则**直接**回退官方 `adb pair`
     （BoringSSL 原生支持 TLS 导出）；并新增 `_adb_pair()`（成功判定兼容中英文回显）与
     `_确保adb可执行()`（adb 无 +x 时 chmod 755）。
  3. `ADB工具.py`：`_run()` 自研模式原本禁止一切 subprocess；改为放行 `adb pair`
     （`_是配对命令()` 判定 `cmd_list[1]=='pair'`），其余命令仍禁止。设备端 shell 的 `_run_no_shell` 保持不变。
- **验证**：`/tmp/test_pair_fallback.py` 单测通过——`_run` 对 pair 放行、对其余命令抛 AdbError、
  `配对设备` 跳过进程内配对并到达 `adb pair`（`ok=True`）。随包 adb 源文件已 `chmod 755`。

## 「手机端一直转圈」真正的环境级根因：5037 被假死 adb server 占住

- 上面三层修复后仍可能失败。实测 `adb pair` 报错：
  `could not install *smartsocket* listener: Address already in use`，
  根因是 **端口 5037 被一个「假死/unresponsive」的 adb server 占住**（lsof 见 LISTEN，
  但 `adb kill-server` 报 `cannot connect to daemon ... timed out`，新 adb 起不来 daemon → 配对卡死）。
- 证据：`/var/folders/.../adb.501.log` 反复 `could not install *smartsocket* listener:
  Address already in use`（跨多小时、多个 adb 路径）；本机曾存在 PID 42259 假死 adb server，已 kill -9。
- **修复（第四层）**：`工具/ADB工具.py` 新增 `_释放adb端口()`，在 `_adb_pair` 内先调用：
  1) `adb kill-server`（优雅，对健康 server 有效）；
  2) 仍占用则按平台强杀占用 5037 的进程——macOS/Linux 用 `lsof -tiTCP:5037 -sTCP:LISTEN`
     取 PID 后 `kill -9`（无 lsof 则 `pkill -f 'platform-tools/adb'` 兜底），Windows 用
     `netstat -ano` + `taskkill /F /PID`。随后 `time.sleep(0.5)` 等内核回收。
- `_释放adb端口` 直接用 `subprocess.run`（绕过 `_run` 的 自研守卫），仅用于释放端口，不触碰设备操作。
- 单测（更新版 `/tmp/test_pair_fallback.py`）确认：`配对设备` 先调用 `kill-server` 再 `adb pair`。
- **重打包（最终）**：15:31 完成，含全部四层修复（含 `_释放adb端口`）。
  `打包/dist/Super_ADB_mac.zip`（63M），SHA256 `234dac4a6d2b10115c863bee42992393d6dc20fdd6f78bf6e32d104d69c0f8fb`。
  包内 adb 可执行（`-rwxr-xr-x`），构建日志无 error/traceback，关键 hidden import 无缺失。
- **用户侧临时缓解**：若扫码仍转圈，终端 `adb kill-server` 杀不掉假死 server 时，用
  `lsof -tiTCP:5037 -sTCP:LISTEN | xargs kill -9` 强杀后再试；新包已自动处理。

## 控制台告警清理（QLayout ×2 + 字体）

- **现象**：app 启动控制台打印
  `QLayout: Attempting to add QLayout "" to 文件管理页 ""`、
  `QLayout: Attempting to add QLayout "" to 日志查看器页 ""`、
  `qt.qpa.fonts: Populating font family aliases took 56 ms. Replace uses of missing font family "微软雅黑"...`。
- **根因**：两页 `__init__` 都先 `_build_ui()`（建布局）+ 后 `inject_widgets()` 又 `setLayout(QVBoxLayout(self))`
  二次设布局 → Qt 告警。字体告警因 `主入口_主题系统.py:272` 品牌标签 CSS 把 Windows 字体 `'微软雅黑'`
  硬编码为首选，macOS 无此字体 → 一次性别名填充开销。
- **修复**：
  1. `页面/文件管理页.py`、`页面/日志查看器页面.py` 的 `inject_widgets()`：清理 `_build_ui` 旧控件后，**安全卸下旧布局**
     （见下方「闪退回归」修正——最初误用 `self.takeLayout()` 已改回 `QLayout.deleteLater()`），不再二次 `setLayout`
     （两页在注入模式仅作逻辑控制器，可见控件来自 .ui，本页不显示）。
  2. `主入口_主题系统.py:272` 品牌标签去掉字面 `'微软雅黑'`，直接用已有的跨平台 `FONT_FAMILY`
     （macOS=PingFang SC / Linux=Noto Sans CJK SC / 其他=微软雅黑）。
  3. 其余运行时代码中字面 `'微软雅黑'`/`'Microsoft YaHei'` 全部改为跨平台字体栈
     （对话框/证书安装、无线调试、ADB终端、页面/小猫 用 FONT_FAMILY；监控 HTML 报告用
     `"PingFang SC", "Microsoft YaHei", ...` / `ui-monospace, Consolas, "Courier New", monospace`）。
     `项目UI/界面样式.py:35` 的 `FONT_FAMILY="微软雅黑"` 是 Windows 兜底分支，保留（Windows 上该字体存在，无告警）。
- **校验**：9 个改动文件 `py_compile` 全通过；运行时代码 grep `微软雅黑` 仅剩 `界面样式.py:35`（预期）。

## ⚠️ 闪退回归（takeLayout 坑）

- **现象**：上一轮「无布局告警」版（SHA `7cdfabcd…`）打包后启动即闪退。
- **根因**：`inject_widgets()` 里写了 `self.takeLayout()` 想卸下旧布局。
  **但本环境 PySide6 6.11.1 的 `QWidget` 并未暴露 `takeLayout()`**（`hasattr(QWidget,'takeLayout')==False`，
  虽 C++ Qt6 有此 API，该绑定没提供）→ `AttributeError` 在 `文件管理页`/`日志查看器页面` 的 `__init__` 抛异常 → 整个 app 启动即崩。
- **修正**：改用 `QLayout.deleteLater()` 安全卸下旧布局（先 `while layout.takeAt(0)` 把子控件 `setParent(None)`，
  嵌套布局也 `deleteLater()`，最后 `old_layout.deleteLater()`）。`页面/文件管理页.py`、`页面/日志查看器页面.py` 均已改。
- **验证**：offscreen Qt 下实跑两页 `inject_widgets()` 不再抛 `takeLayout` 崩溃（`QLayout.deleteLater` 可用）。
- **立即可用回退**：能跑的旧版（含扫码配对四层修复）SHA `234dac4a…` 已恢复到 `打包/dist/`
  （`/tmp/super_adb_trash_1788162148/Super_ADB_mac.zip` 为同一份），用户可先用它。
- **重打包**：后台重建正确版（无崩溃 + 无布局告警），`build_mac_zip.log`，新 SHA256 待补。
