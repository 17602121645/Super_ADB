## 模块职责速查

| 目录 / 文件 | 职责 |
|---|---|
| `Super_ADB_Main.py` | 主窗口、无边框拖拽、托盘、所有按钮信号接线、子目录 `sys.path` 注入 |
| `adb_utils.py` | ADB 命令封装：设备列表、shell 执行、文件推拉、包管理 |
| `ui/Super_ADB.ui` → `Super_ADB.py` | UI 定义与自动生成代码（改 UI 必须走 uic） |
| `dialogs/` | 各独立弹窗，复用窗口模式（重复点击 `raise_` 置顶）；**启动不加载，用到才 import** |
| `dialogs/wireless_debug_dialog.py` | 无线调试总入口，聚合局域网扫描 / 二维码连接 / WiFi 配对三个子模块 |
| `utils/wifi_utils.py` | 纯逻辑：读取本机已保存 WiFi 配置及密码（netsh wlan），供 `wifi_dialog` 调用 |
| `utils/apk_analyzer.py` `analyze_dex.py` `parse_manifest.py` | 离线 APK/DEX/AXML 静态分析脚本（零依赖，可命令行直接跑） |
| `pages/` | 嵌入主窗口的静态分屏页面（日志 / 文件 / 截图），核心页面启动即建 |
| `monitors/` | 后台线程采样的性能监控，ScrollChart 自绘图表；**启动不加载，用到才 import** |
| `hooks/` | 仅供 PyInstaller 打包：收集/重定向 pyzbar 的 zbar DLL，避免冻结后扫码崩溃 |
| `scripts/` | 不参与运行的构建/验证/测试脚本（含 `trace_mem.py` 及 lan_scanner / json_tree / geometry 等测试） |
| `pyinstall_y.py` / `trim_qt.py` | 跨平台打包入口 / 构建后 Qt6 体积裁剪 |

## 依赖关系要点

- 所有模块**扁平裸 import**，无包结构；`Super_ADB_Main.py` 启动时把 `dialogs/ pages/ monitors/ utils/` 加入 `sys.path`（`hooks/` 仅供打包、`scripts/` 仅供测试，不进运行时路径）。
- **启动加载策略（2026-08-09 优化后，2026-08-10 维持）**：顶层只保留 `file_manager_page` / `log_viewer_page` / `popup_style` 及核心依赖；原 11 个重型模块（`device_perf_monitor` / `monkey_runner_window` / `app_perf_monitor` / `install_zip_dialog` / `about_dialog` / `json_tool_dialog` / `md5_dialog` / `timestamp_dialog` / `wireless_debug_dialog` / `wifi_dialog` / `tcpdump_dialog`）改为在对应 `open_xxx` 方法内局部 import。此外 `wireless_debug_dialog` / `wifi_dialog` 作为父模块，会进一步在打开时才拉起 `lan_scanner_dialog` / `qr_connect_page` / `wifi_pair_dialog` / `wifi_history_dialog` 等子模块——**启动阶段整体不加载任何弹窗/监控/扫描模块**（实测 import 主窗口后这些模块均不在 `sys.modules`）。
- 高引用文件留在根目录（`界面样式.py` / `popup_style.py` / `adb_utils.py` / `png_rc.py`），避免大规模改 import。
- `Super_ADB.py`、`png_rc.py`、`*.spec` 相关生成物**禁止手改**；改 UI 走 uic，改资源走 `png.qrc` + 重编译。
- 运行依赖（`requirements.txt`，2026-08-10 实际，2026-08-11 补 pyzbar 说明）：`PySide6` / `Pillow` / `segno`（生成无线调试配对二维码）/ `zeroconf`（mDNS 监听，实现手机扫码配对）/ `ifaddr`（本机 IP 探测，供局域网扫描）。另：`pyzbar`（二维码扫码解码，替代原 OpenCV）由 `pyinstall_y.py` 的 `hidden-import` + `hooks/hook-pyzbar.py` 在打包时引入，`requirements.txt` 未显式声明，运行环境需另行安装（打包产物已自带 `libzbar-64.dll`）。

## 启动内存优化（2026-08-09）

| 级别 | 优化项 | 做法 | 实测收益 |
|---|---|---|---|
| P0 | 延迟 import 重型子模块 | 11 个弹窗/监控模块由顶层 import 改为 `open_xxx` 内局部 import | import 主窗口阶段省下 ~16.9 MB；启动不再加载 matplotlib/numpy 等重型依赖 |
| P0 | 资源文件瘦身 | `ui/png.qrc` 仅保留应用图标，公众号二维码移出资源、改为运行时从 `Super_ADB_Main/resources/公众号.jpg` 磁盘加载；重编译 `png_rc.py` | `png_rc.py` 614 KB → 55 KB；公众号图片字节不再常驻资源内存 |
| P1 | 收敛线程池上限 | `QThreadPool().setMaxThreadCount(6)` → `min(cpu_count, 4)` | 每线程约 1 MB 栈常驻，省 ~2 MB，后台任务并发仍够用 |
| P2 | 内存实测脚本 | 新增 `Super_ADB_Main/scripts/trace_mem.py`（offscreen + tracemalloc + RSS 分阶段测量） | 量化上述优化、便于回归对比 |

> 说明：PySide6 框架本身的 shiboken 绑定层（加载整个 Qt 符号）属固有常驻开销（150–400 MB），不在本项目可优化范围内；本次优化针对「项目自身」的可降占用。实测（`trace_mem.py`，无设备 offscreen）主窗口构造后 RSS ≈ 83.6 MB，重型子模块改按需加载后启动阶段不再额外占用约 16.9 MB。
